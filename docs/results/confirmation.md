# Подтверждающий тест

## Вывод по поиску производительности

Среди проверенных ступеней для подтверждающего теста выбрана
вторая ступень: 200 потоков JMeter, Constant Throughput Timer
300 samples/min на поток, суммарная целевая интенсивность
1000 HTTP-запросов/с.

На второй ступени целевая интенсивность достигалась.
На третьей ступени увеличение цели до 1250 HTTP-запросов/с
не обеспечило её устойчивого достижения:
после переходного пика фактическая частота преимущественно
находилась около 1100–1160 HTTP-запросов/с.

Одновременно клиентский p95 на третьей ступени вырос
примерно до 380–440 мс.

Около 1000 HTTP-запросов/с принято как рабочая точка
для последующего подтверждения, а не абсолютный максимум системы.

Внутри второй ступени отмечено снижение CPU и задержек
при сохранении RPS. Причина изменения режима не установлена;
подтверждающий тест должен проверить воспроизводимость результата.

Вывод относится только к текущему сценарию чтения двух GET,
тестовым данным и установленным ресурсным ограничениям.

На второй ступени обнаружено снижение задержек и CPU
при неизменной интенсивности.

Сравнены два двухсекундных среза JTL до и после изменения.
В обоих срезах каждый GET выполнялся с частотой 500 запросов/с,
все ответы имели HTTP 200 и success=true.
URL, выбранный счёт и распределение размеров ответов сохранились.

Среднее время accounts снизилось с 48,82 до 16,09 мс,
operations — с 65,90 до 20,85 мс.

Снижение частоты запросов и заметное уменьшение ответов
не подтверждены. Перезапуски контейнеров исключены.
Причина уменьшения ресурсной стоимости обработки не установлена.
